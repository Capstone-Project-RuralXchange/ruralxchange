# QA fixes, 12 October 2026

Target: feature/accurate-road-distance. Main is unchanged. These are source fixes,
not a claim that production has been updated or retested.

## Findings

1. Rate limit: configured one trusted Render proxy hop, separate per-IP 300/15min general and 30/15min auth budgets. Health probes bypass the budgets. Frontend 429 errors show retry time. Adjust TRUST_PROXY_HOPS to the actual hosting topology.
2. Login credentials: removed all demo credentials from the login UI. Existing exposed passwords must still be rotated. Seed/docs remain development material, not production credentials.
3. Availability: use inclusive date-range reservations, not one global booked bit. Non-overlapping bookings work. Equipment/specialist reservations and booking inserts use one MongoDB transaction, including bundles. Cancellation removes only its own reservation. Date pickers exclude equipment reservations; the server remains the authority for bundle specialist dates and spans crossing a reservation.
4. Browse: removed Booked status filter. Cards offer Choose dates or Unavailable for maintenance, rather than suggesting that a global booked flag is rentable.
5. Bundles: compatibleSpecialistTypes (or conservative category defaults) enforced in UI and backend. Unknown categories without configured compatible types have no bundle candidates.
6. Repository mismatch: main was old; the target feature branch already contains newer locking and response-window code. Existing road-distance, geocoding and dashboard features are preserved. Replaced separate bundle writes with transaction-backed date reservations. This does not prove this branch exactly matches the deployed source.
7. Cancellation: confirmation and optional reason before status changes; provider dashboards receive cancellation state/reason. No external SMS/email notification was added. Completed work cannot be cancelled.
8. Statistics: provider/specialist incoming bookings counted rather than their seeker-side bookings. Earnings remain completed-work amounts, not promised pending revenue. Seekers do not see earnings.
9. Submission: pending-request toast, stable toast ID, synchronous submit lock preventing double submits.
10. Zero price: existing edit modal uses nullish defaults; zero remains visible and survives save. Rental min/max fields now save and are validated.
11. Dates: typing is blocked in the date picker, years capped at 2100, server rejects malformed/past/reversed dates; same-day rentals count as one day. Pricing is inclusive India calendar days.
12. Sessions/UX: signed-in login redirects to dashboard; browser JWT removed from localStorage and JSON responses, replaced with httpOnly cookie. Cookie-authenticated writes check exact frontend Origin. Booking mobile layout stacks and notes have enough room.
13. Stale requests: past-dated pending requests expire even if auto-cancel is unchecked. Deadline expiration respects the auto-cancel choice. Periodic expiry plus request-time expiry releases stale reservations. Actual old production records are not modified by this source-only change.

Additional safeguards: listing forms cannot overwrite ownership/bookedDates;
unauthorized booking-detail reads rejected; admin self-registration rejected;
raw database errors replaced with safe messages. No promise of a full security audit.

## Before deploying

- Back up production MongoDB. Use a maintenance window and stop the old backend.
- MongoDB must be Atlas/a replica set: standalone MongoDB cannot run these transactions.
- With production MONGODB_URI set, run `npm run migrate:availability --prefix backend` once. This reconstructs reservations from active bookings and changes legacy global `booked` flags to operational `available`; it expires stale pending requests. Never run the destructive seed script against production.
- Set NODE_ENV=production, CLIENT_URL to the exact HTTPS frontend origin (no trailing slash), and TRUST_PROXY_HOPS to the real proxy chain (Render default 1).
- Deploy backend and frontend together. Existing sessions require signing in again. Test actual deployed cookies, proxy IPs, migrations and bookings before calling the live site fixed. Browser third-party-cookie restrictions may require a same-site custom domain/reverse proxy; no production cookie test was possible in this source-only task.
- Rotate exposed admin/demo passwords and the GitHub token pasted in chat. Removing the login box does not invalidate leaked passwords.
- Review and merge/deploy this branch yourself; main was not changed.
